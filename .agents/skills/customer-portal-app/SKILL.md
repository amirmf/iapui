# Customer Portal (`iap-app`) Architecture & Pages

Use this skill when implementing, extending, or maintaining routes, layouts, and feature pages in `apps/iap-app` with exact reference parity to `insurance-ui` (`src/routes/_app/myiap/**` and `src/components/layout/my-iap-*`).

## 1. Application Boundary & URL Conventions

1. **Path Prefix Absence**:
   - In `insurance-ui`, customer pages live under `/myiap/**`.
   - In `apps/iap-app`, the `/myiap` prefix is removed from user-facing routes:
     - Home: `/`
     - My Claims: `/myclaims/`
     - Create Claim: `/myclaims/create/`
     - Special Diseases: `/special-diseases/`
     - Pre-Authorizations: `/pre-auths/`
   - Route root lives under `apps/iap-app/src/app/router/routes/_authenticated/route.tsx` with guard `beforeLoadPublicApp`.

2. **Route Files**:
   - Keep route files thin: route definition, search validation, loaders, and delegation to the owning feature's public API.

## 2. Layout Architecture (`MyIapLayout` / `AppShell`)

The customer portal layout is located at `apps/iap-app/src/shared/app-shell/my-iap-layout.tsx` (with `AppShell` re-exported for backwards compatibility):

```text
MyIapLayout
├── LayoutLoading                  # Checks authentication session, renders Loader2 spinner
└── SupportFlowProvider            # Shared support flow context for tickets and bot
    └── div (min-h-screen)
        ├── MyIapHeader            # Fixed top bar with dynamic tenant theme background
        │   ├── Logo & Brand       # VITE_LOGIN_LOGO, VITE_LOGIN_COMPANY
        │   ├── Desktop Nav Links  # Home, My Claims, Special Diseases, Create Claim
        │   ├── AppPanelSwitcher   # 4 panels: Evaluation, Agent, Customer, Customer-User
        │   └── MyIapUserActions   # Theme switcher, avatar/name button, dropdown with logout
        ├── Spacer div (h-14)      # Offsets the fixed header
        ├── main (#main-content)   # Outlet or injected children with rtl direction
        ├── MyIapFooter            # Desktop footer with navigation links and copyright
        ├── MyIapBottomNav         # Mobile bottom navigation bar with active theme colors and bot trigger
        ├── SupportFlowWidget      # Desktop floating bot trigger and chat window
        ├── ForcePasswordChangeDialog
        └── AuditInformationDialog
```

## 3. Dynamic Theming & Tenant Customization

1. **Branded Background Colors**:
   - `MyIapHeader` and `MyIapBottomNav` active indicators dynamically apply tenant colors:
     ```ts
     const theme = useThemeStore((state) => state.theme)
     const activeColor =
       theme === 'dark'
         ? import.meta.env.VITE_MY_IAP_NAV_BACKGROUND_DARK
         : import.meta.env.VITE_MY_IAP_NAV_BACKGROUND
     ```
   - Generated by `tools/prepare-tenant.mjs` from `tenants/<tenant>/brand.json`.

2. **Panel Switcher**:
   - Registers all 4 authorized panels in reference order:
     1. Evaluation (`admin`): `VITE_IAP_ADMIN_DOMAIN_URL` (`/`)
     2. Agent (`agent`): `VITE_IAP_ADMIN_DOMAIN_URL` (`/agent/claim-requests/`)
     3. Customer (`app`): `VITE_IAP_APP_DOMAIN_URL` (`/`)
     4. Customer-User (`customerUser`): `VITE_IAP_ADMIN_DOMAIN_URL` (`/customer-user/`)
   - Uses `tone='inverted'` for contrast against the branded header.

## 4. Component Placement & Standards

- Layout and shell components belong in `apps/iap-app/src/shared/app-shell/`.
- Customer feature journeys belong in `apps/iap-app/src/features/<feature>/`.
- Do not create `ui/` directories; use `components/`. Reusable cross-application primitives come from `@iap/ui`.
- All visible strings must be localized in `apps/iap-app/src/shared/i18n/locales/fa/common.json`.
- Follow strict typing: add all tenant variables to `apps/iap-app/src/vite-env.d.ts`.
