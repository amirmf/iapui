# Customer Portal (`iap-app`) Architecture & Pages

Use this skill when implementing, extending, or maintaining routes, layouts, and feature pages in `apps/iap-app` with exact reference parity to `insurance-ui` (`src/routes/_app/myiap/**` and `src/components/layout/my-iap-*`).

## 1. Application Boundary & URL Conventions

1. **Path Prefix Absence & Full Route Matrix**:
   - In `insurance-ui`, customer pages live under `/myiap/**`.
   - In `apps/iap-app`, the `/myiap` prefix is removed from user-facing routes, canonicalized with trailing slashes:
     - Home: `/` (`_authenticated/index.tsx`, crumb: `myiap`)
     - My Claims: `/myclaims/` (`_authenticated/myclaims/index.tsx`, crumb: `myClaims`)
     - Create Claim: `/myclaims/create/` (`_authenticated/myclaims/create/index.tsx`, crumb: `createClaim`)
     - Claim Details: `/myclaims/$id/` (`_authenticated/myclaims/$id.index.tsx`, crumb: `claimDetails`)
     - Special Diseases: `/special-diseases/` (`_authenticated/special-diseases/index.tsx`, crumb: `mySpecialDiseases`)
     - Create Special Disease: `/special-diseases/create/` (`_authenticated/special-diseases/create/index.tsx`, crumb: `createMySpecialDisease`)
     - Special Disease Details: `/special-diseases/$id/` (`_authenticated/special-diseases/$id.index.tsx`, crumb: `mySpecialDiseaseDetails`)
     - Pre-Authorizations: `/pre-auths/` (`_authenticated/pre-auths/index.tsx`, crumb: `preAuths`)
   - Route root lives under `apps/iap-app/src/app/router/routes/_authenticated/route.tsx` with guard `beforeLoadPublicApp`.

2. **Route Files & Dynamic Params**:
   - Keep route files thin: route definition, search validation, loaders, and delegation to the owning feature's public API.
   - Static segments use dedicated directories with `index.tsx` (e.g. `myclaims/create/index.tsx`).
   - Dynamic parameters map to flat file routes with `.index.tsx` (e.g. `myclaims/$id.index.tsx`). Verified in `apps/iap-app/src/shared/router/customer-routes.test.ts`.

        ├── SupportFlowWidget      # Desktop floating bot trigger and chat window

## 3. Dynamic Theming & Tenant Customization

1. **Branded Background Colors**:
   - `MyIapHeader` and `MyIapBottomNav` active indicators dynamically apply tenant colors:
     ```ts
     const theme = useThemeStore((state) => state.theme)
     const activeColor =
       theme === 'dark'
         ? import.meta.env.VITE_MY_IAP_NAV_BACKGROUND_DARK
         : import.meta.env.VITE_MY_IAP_NAV_BACKGROUND
     ```
   - Generated by `tools/prepare-tenant.mjs` from `tenants/<tenant>/brand.json`.

2. **Panel Switcher**:
   - Registers all 4 authorized panels in reference order:
     1. Evaluation (`admin`): `VITE_IAP_ADMIN_DOMAIN_URL` (`/`)
     2. Agent (`agent`): `VITE_IAP_ADMIN_DOMAIN_URL` (`/agent/claim-requests/`)
     3. Customer (`app`): `VITE_IAP_APP_DOMAIN_URL` (`/`)
     4. Customer-User (`customerUser`): `VITE_IAP_ADMIN_DOMAIN_URL` (`/customer-user/`)
   - Uses `tone='inverted'` for contrast against the branded header.

## 4. Component Placement & Feature Architecture

1. **Single-Route vs Multi-Journey Features**:
   - **Single-Route Features** (e.g. `pre-auths`, which have no sibling sub-pages like `create/` or `$id/`):
     - Place the page component directly in the feature root: `src/features/<feature>/<feature>-page.tsx`.
     - **Do NOT** create a redundant `pages/` or `pages/index/` directory.
     - Page-exclusive components live in `src/features/<feature>/components/`.
     - Feature public barrel `index.ts` re-exports the page component and public contracts.
   - **Multi-Journey Features** (e.g. `myclaims`, `special-diseases` which have `create/` and `$id/` journeys):
     - Keep page journeys in `pages/<journey>/` (e.g. `pages/index/`, `pages/create/`).
     - Sibling-shared components live under feature `components/`.

2. **Customer Filter & Form Fields Pattern**:
   - Filter components wrap `@iap/forms` `<Form {...form}>` and compose dedicated form field components:
     - `MyClaimMyInsurancePolicyFormField`: Renders policy `SearchableSelect`, auto-selects first policy, resets dependent national code, supports `isFilter` and optional `SupportFeatureButton`.
     - `MyClaimMyNationalCodeFormField`: Watches `extPolicyId`, fetches dependents via `useGetMySubInsuredPeople({ policyId })`, formats labels with foreign indicator, supports `isFilter` and optional `SupportFeatureButton`.
   - Lookup services and hooks belong in `src/modules/` (e.g. `@modules/insurance-policies`, `@modules/sub-insured-people`), enabling clean cross-feature reuse without violating feature boundaries.

3. **Card Grid & Dual Pagination Pattern**:
   - Page size: `const PAGE_SIZE = 9`.
   - Grid layout: `-mx-2 flex flex-wrap` with item class `mb-4 w-full px-2 md:w-1/2 lg:w-1/3`.
   - Dual pagination: placed above (`border-b pb-4`) and below (`border-t pt-4`) the card grid.
   - End of list protection: when server returns empty content for `page > 0`, open `ConfirmDialog` to step back to `page - 1` automatically.
   - Translations: pagination uses `myClaimRequests.previous`, `myClaimRequests.pageIndicator`, `myClaimRequests.next`, and `countTranslationKey`.

4. **Icons & Styling**:
   - Use `lucide-react` for shared standard icons (e.g. `RotateCwIcon`, `ArrowRightIcon`).
   - Compose classes via `cn` from `@iap/ui`.

## 5. Home Page (`MyIapPage`) & Bank Account Patterns

1. **Single Public Export**:
   - `apps/iap-app/src/features/home/index.ts` strictly exports `MyIapPage` (no multiple or alias exports).
   - Route `/_authenticated/index.tsx` delegates directly to `MyIapPage` with `loader: () => ({ crumb: 'myiap' })`.

2. **Iranian IBAN (Sheba) Validation Pattern**:
   - Algorithm: ISO 7064 Mod 97-10 checksum (`isValidIranianIban`), checking Iranian bank code table (`iranianIbanBanks`) and temporarily unsupported banks (`temporarilyIgnoreIbanBankCodes`).
   - Model: `myBankAccountFormSchema(t)` combines length, regex, checksum, and bank code restrictions with localized messages.
   - Form description: `IbanBankNameDescription` displays bank name via `@iap/forms` `FormDescription`.

3. **Policy Action Patterns**:
   - **PDF Download**: checks policy ID against `hasPolicyPdf(id)` (`policyPdfIds = [41245888]`) and programmatically triggers anchor download for `/policy/${id}.pdf`.
   - **Bank Account / Support Check**: `useHasHozeSupportPolicyIds` suppresses bank account action if user holds eligible Hoze support policy (`hozeSupportPolicyIds`).

4. **Animated Border Action Cards**:
   - `<Link className='no-underline'><div className='animated-border-card'><Card className='h-full cursor-pointer border-0 transition-colors duration-300 hover:bg-primary-50/30'>...`.
